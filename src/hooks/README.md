# hooks

Hooks generated by the shadcn CLI, nothing else. The folder exists only because `components.json`
declares the `@/hooks` alias and the registry writes here.

## Belongs here

CLI output. `use-mobile.ts` is here because `components/ui/sidebar.tsx` depends on it — it was not
chosen, it arrived with `pnpm dlx shadcn@latest add sidebar`.

## Doesn't belong here

Application hooks. Anything that knows what a project, link, run or listing is lives next to its
feature (`src/features/<feature>/useProjects.ts`, `useRun.ts`, `useFindings.ts`) so its logic sits
beside the component that uses it.

## Gotchas

- Deleting a `ui/` component does not delete the hook it dragged in. `use-mobile` is dead the moment
  `sidebar.tsx` goes.
