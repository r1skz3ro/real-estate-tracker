# components/ui

shadcn/ui primitives, generated by the CLI: `pnpm dlx shadcn@latest add <name>`.

## Belongs here

CLI output, added one component at a time as something actually needs it — not a bulk install.

## Doesn't belong here

Hand-written components, and any domain knowledge. These files must stay generic enough that
re-adding them from the registry is a non-event.

## Gotchas

- **Hand-edits must survive a re-add.** All of them are the same one: the overlay in
  `alert-dialog.tsx`, `dialog.tsx` and `sheet.tsx` is bumped to `bg-black/60` because the default
  `bg-black/10` is invisible on a dark background. Re-adding any of those three silently reverts it.
- **`sidebar.tsx` needs theme tokens the registry does not ship.** Its entry has no `cssVars`, so
  the six `--sidebar-*` variables in `src/styles.css` were added by hand. Without them the sidebar
  renders transparent with no active state, and re-adding `sidebar` will not bring them back.
- **`sidebar.tsx` ships a broken active state.** It styles on `data-active:`, which Tailwind
  compiles to attribute _presence_, but sets `data-active={isActive}` — and React writes `false`
  out as the string `"false"`. Every menu item then looks active. Both set-sites are hand-edited to
  `isActive || undefined`; re-adding `sidebar` reverts it.
- This is the only place in the app allowed to use `dark:` variants — they are part of the
  generated output. App code never writes them; the app is dark-only by design.
